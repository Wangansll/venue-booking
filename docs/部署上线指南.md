# 部署上线指南（腾讯云轻量 + 域名 + HTTPS）

> 面向：一台全新 Ubuntu 22.04 服务器 + 一个域名。
> 全程约 1 小时（不含备案等待），不需要懂 Docker 也能照着敲。

---

## 0. 先决定：要不要备案

| 方案 | 访问方式 | 备案 | 适合 |
|---|---|---|---|
| **A. 国内服务器 + IP 访问** | `http://公网IP:8080` | **不需要** | 想马上上线、先看效果 |
| **B. 国内服务器 + 域名** | `https://venue.你的域名.com` | **必须备案**（7–20 天） | 长期、正式对外 |
| **C. 香港/新加坡服务器 + 域名** | `https://venue.你的域名.com` | 不需要 | 想立刻用域名+HTTPS |

**关键事实**：备案只卡「域名 + 80/443」。用 IP + 非标端口访问**不需要备案**。

本指南以 **B/C** 为目标（Caddy 自动 HTTPS），A 的差异在每节末尾标注。

---

## 1. 买什么

| 项 | 配置 | 价格参考 |
|---|---|---|
| 轻量应用服务器 | **2 核 2G / 40G SSD / 3M 带宽**，Ubuntu 22.04 | ¥100–200/年（学生机更便宜） |
| 域名 | `.com` / `.cn`，任意 | 首年 ¥1–30 |

> 你的账户余额只有 ¥4.08，**先充值再买**。买之前确认已实名认证（你已经认证过了）。

## 2. 服务器初始化

用腾讯云控制台的「OrcaTerm」或本地 SSH 登录：

```bash
ssh root@你的公网IP
```

### 2.1 建普通用户（别一直用 root）

```bash
adduser deploy
usermod -aG sudo deploy
# 把本地公钥贴进去（没有就先生成：ssh-keygen -t ed25519）
mkdir -p /home/deploy/.ssh
echo "你的公钥内容" > /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys
```

### 2.2 安全基线

```bash
# 改 SSH 端口并禁用密码登录（改完先别退出，另开窗口验证能进再关旧的）
sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
systemctl restart ssh

# 时区
timedatectl set-timezone Asia/Shanghai

# 2G 内存加 swap（编译前端时救命）
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 系统更新
apt update && apt upgrade -y
```

### 2.3 防火墙

腾讯云控制台「防火墙」放行 **22 / 80 / 443**。
服务器内：

```bash
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp
ufw --force enable
```

> **方案 A 额外**：放行你选的应用端口（如 8080），并跳过第 6 步的 Caddy。


## 5. 配置生产环境变量

在项目根目录（有 `docker-compose.prod.yml` 那层）：

```bash
cp .env.example .env
```

生成强密钥（**不要手写，不要用示例值**）：

```bash
echo "DB_PASS=$(openssl rand -base64 24)"
echo "JWT_SECRET=$(openssl rand -hex 32)"
```

编辑 `.env`：

```bash
nano .env
```

```ini
DB_PASS=刚才生成的数据库密码
JWT_SECRET=刚才生成的 64 位十六进制
DOMAIN=venue.你的域名.com
ACME_EMAIL=你的邮箱@example.com
CORS_ORIGINS=https://venue.你的域名.com
PAY_PROVIDER=mock
NOTIFY_PROVIDER=console
```

```bash
chmod 600 .env   # 只允许本人读
```

> **`JWT_SECRET` 少于 32 位或含 `change-me` 之类弱口令，服务会直接启动失败**——这是故意的保护。

## 6. 域名解析

在域名服务商（腾讯云 DNSPod / 阿里云）添加记录：

| 主机记录 | 类型 | 值 | TTL |
|---|---|---|---|
| `venue` | A | 服务器公网 IP | 600 |

验证（在自己电脑上）：

```bash
nslookup venue.你的域名.com
# 应返回你的服务器 IP
```

**等解析生效（几分钟）再做下一步**，否则 Caddy 申请证书会失败。

> **方案 C（香港节点）**：同样解析，无需备案，直接走第 7 步。
> **方案 A（无域名）**：跳过第 6、7 步，见第 8 节末尾。

## 7. 一键启动

```bash
cd ~/venue-booking
docker compose -f docker-compose.prod.yml up -d --build
```

首次会：拉 MySQL → 装 Node → **构建前端** → 跑迁移 → 起服务 → Caddy 申请证书。
**2 核 2G 大约 5–8 分钟**，看进度：

```bash
docker compose -f docker-compose.prod.yml logs -f
```

看到类似就成功了：

```
caddy  | certificate obtained successfully
app    | {"level":"info","msg":"API 已启动 http://127.0.0.1:8787/api/health"}
```

### 初始化演示数据（只第一次）

```bash
docker compose -f docker-compose.prod.yml exec app node src/seed.js
docker compose -f docker-compose.prod.yml exec app node src/seed-tickets.js
docker compose -f docker-compose.prod.yml exec app node src/seed-articles.js
```

> 正式运营时**不要**跑 seed，改为在后台自己建场次（`/admin/sessions` 已经支持自动生成座位）。

## 8. 上线验收

打开 `https://venue.你的域名.com`，逐条核对：

| # | 检查 | 期望 |
|---|---|---|
| 1 | 地址栏 | 🔒 锁图标，https 无警告 |
| 2 | 首页 | 轮播、场馆、活动、新闻都正常 |
| 3 | `https://域名/api/health/ready` | `{"ready":true,"migrations":8}` |
| 4 | 登录 `student / 123456` | 能进 |
| 5 | `/tickets/1` 选座 | 座位图正常，二维码可显示 |
| 6 | `/admin`（`admin/admin123`） | 票房有数字 |
| 7 | 手机打开同地址 | 布局正常（这是重点） |

**⚠️ 上线后第一件事：改掉演示账号密码**

```bash
# 连进数据库改密码（密码用 scrypt 哈希，别手写明文）
docker compose -f docker-compose.prod.yml exec app node -e "
const {scryptSync,randomBytes}=require('crypto');
const h=(p)=>{const s=randomBytes(16);return s.toString('hex')+':'+scryptSync(p,s,64).toString('hex')};
console.log('新密码哈希：', h('你的新密码'));
"
```

拿到哈希后 `UPDATE users SET password_hash='...' WHERE username='admin';`

> **方案 A（IP 访问，无域名）**：把 `docker-compose.prod.yml` 里 `caddy` 段删掉，
> 给 `app` 加 `ports: ["8080:8787"]`，访问 `http://公网IP:8080` 即可，无需证书。

## 9. 日常运维

### 备份（每天 3 点自动）

```bash
crontab -e
# 加一行
0 3 * * * cd /home/deploy/venue-booking && docker compose -f docker-compose.prod.yml exec -T mysql mysqldump -uroot -p$DB_PASS venue_booking | gzip > /home/deploy/backup/venue-$(date +\%F).sql.gz
```

先建目录：`mkdir -p /home/deploy/backup`
保留 14 天：再加一行 `find /home/deploy/backup -name "*.sql.gz" -mtime +14 -delete`

**每月做一次恢复演练**（这是关键，没演练过的备份等于没备份）：

```bash
gunzip -c 备份文件.sql.gz | docker compose -f docker-compose.prod.yml exec -T mysql mysql -uroot -p你的密码 venue_booking
```

### 更新代码

```bash
cd ~/venue-booking
git pull
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml exec app node src/migrate.js   # 有新迁移时
```

### 回滚

```bash
git log --oneline -5
git checkout 上一个提交

```

### 看日志 / 查问题


## 10. 常见坑（按出现概率排）

| 现象 | 原因 | 解法 |
|---|---|---|
| **Caddy 拿不到证书** | 域名没解析到本 IP / 80 端口没放行 | 先 `nslookup` 确认，再查控制台防火墙 |
| **502 Bad Gateway** | app 容器没起来 | `docker compose ps` 看 app 是否 restarting，再 `logs app` |
| **数据库连不上** | migrate 容器失败 | `logs migrate`；多半是 `.env` 里 `DB_PASS` 为空 |
| **启动即退出，日志写 JWT_SECRET** | 密钥太短或含弱口令 | 用 `openssl rand -hex 32` 重新生成 |
| **上传图片 404** | uploads 卷没挂 | 确认 `app` 服务有 `- uploads:/app/uploads` |
| **构建前端时 Killed** | 内存不足（1G 机器） | 加 swap（第 2.2 节），或升级到 2G |
| **备案没过，域名打不开** | 国内 80/443 被拦 | 等备案；或先用 IP:端口 访问 |
| **时间不对（场次都过期）** | 容器时区 | compose 里给 app 加 `TZ: Asia/Shanghai` |
